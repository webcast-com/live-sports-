# ScoreHub - Full Audit & Upgrade Roadmap
**Date: 2026-07-28 | Branch: arena/019fa6a7-new-chat**

---

## 1. Executive Summary
ScoreHub is a live sports dashboard (live scores, predictions, sure-bets, premium) built with React 18 + Vite + Tailwind + Supabase. Functionality exists but **major wiring mismatches** prevent SEO, shareable URLs, and production safety.

**Critical blockers:**
- `Livescoredashboard2/` has **no `index.html`** – build falls back to `/index.html` at repo root, which belongs to a completely different product "Hyperlink Social Connect". Crawlers see wrong title/description.
- `src/app/routes.tsx` (react-router) is defined but **never used**. `App.tsx` renders only `AppLayout` which does manual `window.history.pushState` routing.
- SEO is 100% client-side via `setPageMeta()` → invisible to bots without JS. Sitemap static contains 1 URL, outdated domain.
- Supabase credentials hardcoded in `utils/supabase/info.tsx` (autogenerated) – should be env. Payment upgrade is client-side only, no webhook verification (can be spoofed).
- Duplicate codebase: `/src/livescore/*` and `/Livescoredashboard2/src/*` – drift risk.

Overall: **Pages semi-wired, DB access working but fragile, SEO broken.**

## 2. Pages & Wiring Audit

### Current Routing:
**AppLayout.tsx (actual router):**
```ts
const tabPaths = { dashboard: '/', predictions: '/predictions', results: '/results', sure-bets: '/sure-bets', premium: '/premium', settings: '/settings', subscription: '/subscription', webhook: '/webhook' }
const informationalPages = { about, careers, press, contact, advertise, partners, help, terms, privacy, cookies, accessibility }
```
- Uses `window.history.pushState` + `popstate` listener.
- `activeSport` filter (all, football, basketball...) is **state only**, not in URL → not shareable/bookmarkable, breaks back button expectation.
- Footer links call `onNavigate` else `window.location.href` → full reload fallback.
- No 404. Unknown path falls back to dashboard silently.
- `MatchDetail` route `/match/:id` defined in `routes.tsx` but unreachable in AppLayout. FeaturedMatch is modal only.
- Breadcrumb builds JSON-LD via inline `<script>` using `window.location.origin` in render → SSR unsafe, also rendered twice (once per navigation, no cleanup).

**Header.tsx / TabNavigation.tsx / Footer.tsx**
- Sport tabs UI inert (only state), no `?sport=football`.
- TabNavigation has inline style `backgroundColor: 'rgba(158,86,16,1)'` hardcoded – design token leak.

**Verdict:** **5/10** – Works for SPA demo but not production. Need real router.

### Fix (Quick Win):

1. **Use BrowserRouter in App.tsx:**
```tsx
import { BrowserRouter } from 'react-router'
import { router } from './routes'
// or create new router with all tabs
```
2. Unify `routes.tsx` to include all tabs + informational + sport param:
```tsx
{ path: "/", Component: AppLayout, children: [
  { index: true, element: <Dashboard /> },
  { path: "predictions", element: <PredictionsList /> },
  { path: "sport/:sport", element: <Dashboard /> },
  ...
]}
```
3. Sport in URL: `/sport/football` or `/?sport=football`, sync via `useSearchParams`.
4. Add `NotFound.tsx`.

## 3. Database & API Access Audit

### Supabase Config:
- Project ID `vgofxfjbcaplgrhodxmn` exposed in two places:
  - `Livescoredashboard2/utils/supabase/info.tsx`
  - `src/livescore-supabase/info.ts`
- Anon key hardcoded – ok for public but should be `VITE_SUPABASE_ANON_KEY`.
- `supabase.ts` imports from `/utils/supabase/info` (absolute path alias may break in CI if alias not mapped – vite alias only maps `@` → `./src`).

### Tables (from `supabase_setup.sql`):
- `user_profiles`, `user_preferences`, `user_plans`, `payment_logs`, `usage_logs`, `verification_tokens`
- RLS enabled, policies per user_id – **good**.
- View `user_account_summary` grants select to `anon` – potential information leak if RLS not applied to view? Should revoke anon.
- Triggers auto-create profile/preferences/plan on signup – **good**.

### AuthContext.tsx:
- Handles free→premium with expiry check, auto downgrade.
- `upgrade()` does `upsertUserPlan` client-side + inserts `payment_logs` without verifying Paystack reference – **security hole**: user can call upgrade with fake ref and get premium.
- No realtime sync for plan changes.
- `fetchUserPreferences` returns `undefined` not null if not found – causes type mismatch.

### Data Fetching:
- `ScoreSimulator.ts` (Live scores): tries Supabase Edge `make-server-ed1dd9fb/matches/live`, then falls back to `liveMatches` mock. Has localStorage cache 5min, poll 30s. But:
  - Controlled by `VITE_ENABLE_LIVE_SPORTS_API` flag – if false, always mock (prod may ship mock accidentally).
  - Logs heavily to console – leaks info.
  - No AbortController reuse, no visibility pause.
- `UpcomingMatchesHook.ts`: similar but only checks `state.description` for upcoming – API format may change.
- `useNewsHook.ts` / `useTransfersHook.ts`: fetch via edge functions `football-news`, `football-transfers`. No caching, silent fallback.
- `supabaseApi.ts` (`fetchSupabaseApi`): generic proxy to `functions/v1/rapidapi?service=...` – forwards anon key in Authorization header, ok, but no retry, no rate limit handling.
- `apiClient.ts` (`corsFetch`): tries direct fetch then 5 public CORS proxies (corsproxy.io, codetabs...). These proxies are dead/unreliable and strip RapidAPI headers → guaranteed fail for RapidAPI auth. Should be removed, rely solely on Supabase edge.
- `PredictionsList.tsx`: mixes mock + live predictions, UI shows raw JSON toggle – good for debugging but leaks raw API structure in prod.

### Edge Functions (`supabase/functions/server/index.tsx`):
- Handles 8 endpoints (matches/live, upcoming, match/:id, stream, highlights, standings, event detail...). Each reads separate env vars for RapidAPI keys (FOOTBALL_HIGHLIGHTS, LIVE_STREAM, ALLSPORTS, etc) – good separation but:
  - Returns `200` with empty `[]` even on error (hides rate limit 429). Frontend thinks success.
  - No authentication on edge functions – anyone with anon key can spam RapidAPI quota.
  - No caching headers (`Cache-Control`).
  - No request ID logging.

**Verdict:** **6/10** – Works but not secure/prod-ready.

### Upgrades:

**Immediate:**
- Move credentials to `.env`: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Delete `utils/supabase/info.tsx` from git.
- Fix Paystack: only upgrade via webhook. Client `upgrade()` should not write plan; webhook should verify reference via Paystack API then update `user_plans`.
- Contact form: wire to `send-contact-email` function instead of fake setTimeout.
- Remove corsproxy fallback, keep only Supabase edge.
- Add TanStack Query for caching, deduplication, background refetch:
```ts
useQuery({ queryKey: ['matches', activeSport], queryFn: fetchLive, staleTime: 30_000, refetchInterval: 30_000 })
```
- Add `visibilitychange` listener to pause polling when tab hidden.

**Medium:**
- Add Supabase Realtime for live scores: `supabase.channel('live-scores').on('postgres_changes', ...)`
- Add request caching at edge: Deno KV or Upstash Redis 60s for matches.
- Rate limiting via `hono-rate-limiter`.
- Centralize API client: one `fetchEdge(path, params)` helper with retries, zod validation.
- Move to RLS-secured `payment_logs` status = pending → success only via webhook.

## 4. SEO & Meta Tags Audit

### Current State:
- **seoMeta.ts**: excellent coverage – 21 pages, title, description, keywords, og, twitter, canonical defined. However:
  - `liveScores` key defined but AppLayout maps `dashboard` → `home`, so `/live-scores` never used. TabPaths uses `/` for dashboard, but seoMeta has `liveScores` canonical `/live-scores` → canonical mismatch → duplicate content risk.
  - `leaderboard`, `results`, `sureBets` vs `results` tab? some keys not aligned with tabKeys.
  - OG image `https://livescoresgames.netlify.app/og-image.png` – file does not exist in `public/`. 404 → social previews broken.
  - `setPageMeta` creates tags if missing, but does NOT remove old tags when navigating? Creates duplicates if meta already exists with different casing. Also no cleanup for `og:url`.
  - No `<meta name="robots">`, no `hreflang`.
  - No JSON-LD beyond breadcrumb (in Breadcrumb.tsx). Should have SportsEvent, Organization, FAQ.

- **index.html (root)**: THIS IS WRONG. Contains:
```html
<title>Hyperlink Social Connect | Connect, Create, Belong</title>
<meta property="og:url" content="https://hyperlink.hyper.co.ke/" />
```
If Netlify deploys from `Livescoredashboard2/`, it won't find index.html and fallback to root? Vite will look for `index.html` in `Livescoredashboard2/` and fail to build. Local dev may work because root index exists but SEO is for another product. **Critical**.

- **robots.txt**: 
```
User-agent: *
Allow: /
Sitemap: https://livescoresgames.netlify.app/sitemap.xml
```
Ok but references old netlify domain, not custom domain. No disallow for `/settings`, `/subscription`, `/webhook` (private). Should add.

- **sitemap.xml**: static, only 1 URL. Generator `sitemapGenerator.ts` generates 6 routes + 5 sport routes = 11 URLs, but **excludes** informational pages (`/about`, `/contact`, etc) which are important for SEO. Also only runs on `writeBundle` → not generated in dev, and only if `Livescoredashboard2/dist` exists.

**Verdict:** **3/10** – Structure exists but broken deployment.

## 5. Security, Performance & UX Gaps

- **Auth**: No OAuth (Google). Password reset flow exists but not tested.
- **Paystack**: KSh 100 hardcoded, no currency switch, no coupon.
- **No PWA**: add `vite-plugin-pwa` for offline scores.
- **No analytics consent**: GTM + gtag loaded without cookie consent (GDPR violation).
- **Accessibility**: `alt` texts ok, but tab navigation not keyboard-accessible (`TabNavigation` uses buttons but sport pills lack aria).
- **Performance**: No lazy loading for `PredictionsList`, `PremiumUpgrade`, etc. All imported synchronously in AppLayout → large bundle. Use `React.lazy`.
- **Bundle**: `motion`, `recharts`, `mui/icons` all bundled even if not used on dashboard first paint.
